# Contract: Site pages, URLs and assets

Phase 1 output for [spec.md](spec.md). This is the interface the site exposes to visitors and
the obligations every page carries. The site's "API" is its URLs.

## URLs

Pages are served at the repository's Pages URL (`https://tosin2013.github.io/animspec/`); all
internal links are relative, so the site works unchanged under any host or local preview.
VitePress derives each URL from its markdown filename.

| URL | File | Source |
| --- | --- | --- |
| `/` | `docs/index.md` | handwritten |
| `/gallery/` | `docs/gallery.md` | generated by `npm run site:generate` |
| `/contribute/` | `docs/contribute.md` | handwritten |
| `/user-guide/` | `docs/user-guide.md` | existing document, rendered in place |
| `/deployment/` | `docs/deployment.md` | existing document, rendered in place |
| `/DESIGN_DOC/` | `docs/DESIGN_DOC.md` | existing document, rendered in place |
| `/vocabulary/` | `docs/vocabulary.md` | generated copy of the root `VOCABULARY.md` |
| `/contributing/` | `docs/contributing.md` | generated copy of the root `CONTRIBUTING.md` |

Nav contract: the theme nav links home, gallery and contribute on every page; the sidebar groups
the documents under "Documentation". The proposal issue template is reachable from the home page
in at most two clicks (SC-002).

## Page obligations

### `/` (home)

1. The determinism promise, stated as the README's promise table (same rows, same guarantees,
   linked to the README as the source of truth).
2. At least one sample loop, drawn by the library, animating on the page, with a caption saying
   exactly that: rendered by the committed library, deterministically, from a fixed seed.
3. The install command, `npm install animspec`, copyable.
4. The quick-start example: validate, build a `SignalFrame`, draw. It MUST match the user
   guide's quick start; the guide is canonical, the page links it.
5. Links: user guide, software design document, gallery, contribute, npm package page,
   repository root.

### `/gallery/` (generated)

1. One card per registry primitive (SC-003): thumbnail with alt text, `type` (heading),
   `category`, `tier`, `description` verbatim from the registry, an animated loop
   (`docs/public/loops/<type>.gif`, generated by `npm run loops:generate`), and a link to the
   primitive's entry in `src/primitives/registry.ts` on GitHub.
2. A `legacy` card names the primitive that replaces it, when `replacedBy` is set.
3. A lead-in sentence linking the vocabulary page for the full param tables: the card is a
   picture and a name, the vocabulary is the reference.

### `/contribute/` (contribute)

1. The new-primitive rule and the four style questions, summarised, each linking the
   contributing page.
2. The five steps in order: open a proposal issue from the template, implement one registry
   entry, run `npm run verify`, sign the CLA, open the pull request.
3. The gates behind `npm run verify`, stated as the contributor's one-command quality bar.
4. Links: the primitive-proposal template, the CLA, `good first primitive`, the contributing
   page, the user guide's "write a spec" material for trying primitives before proposing one.

### Document pages

- Rendered from the committed markdown: `docs/user-guide.md`, `docs/deployment.md`,
  `docs/DESIGN_DOC.md` in place; `VOCABULARY.md` and `CONTRIBUTING.md` copied by the generator
  (see [generator.md](generator.md)). No document's content is edited for the site; the site
  adds a reading experience (nav, sidebar, search), never a second version of the truth.
- Mermaid fences in `DESIGN_DOC.md` are rendered by the theme's diagram support, or fall back to
  the fenced code block on GitHub if the theme does not enable it.

## Asset rules

- Theme assets: VitePress's default theme ships all CSS, JS and icons inside the built output.
  The optional customisation lives in `docs/.vitepress/theme/` and stays a CSS tweak: a
  monochrome accent matching the library's palette, and optionally the shipped font layer.
- Fonts: optional `@font-face` over the shipped font files copied to `docs/public/fonts/`, each
  with its licence text beside it, over the theme's system font stack. A page MUST NOT load a
  font from any other origin.
- Search: local and bundled (VitePress's built-in local search). Remote search services are not
  configured.
- A page load MUST issue zero requests to origins other than the site's own (SC-004). No
  analytics, no CDN, no web fonts, no images from outside the artifact.

## Accessibility and semantics

- The theme provides responsive layout, focus states and a skip-to-content link; the custom CSS
  tweak MUST NOT reduce contrast below WCAG AA.
- Every image has alt text; thumbnail alt text is `"<type>: <description>"`.
- Content pages work with JavaScript disabled; only the bundled local search needs it.

## 404 behaviour

VitePress's build emits the theme's 404 page. No custom error page at v1 (out of scope, recorded
here so its absence is a decision, not an oversight).
