# Contract: Site pages, URLs and assets

Phase 1 output for [spec.md](spec.md). This is the interface the site exposes to visitors and
the obligations every page carries. The site's "API" is its URLs.

## URLs

Pages are served at the repository's Pages URL (`https://tosin2013.github.io/animspec/`); all
internal links are relative, so the site works unchanged under any host or local preview.

| URL | File | Source |
| --- | --- | --- |
| `/` | `site/index.html` | handwritten |
| `/gallery/` | `site/gallery.html` | generated by `npm run site:generate` |
| `/contribute/` | `site/contribute.html` | handwritten |

Nav contract: every page links the other two. The landing page is reachable from any page in one
click; the proposal issue template is reachable from the landing page in at most two (SC-002).

## Page obligations

### `/` (landing)

1. The determinism promise, stated as the README's promise table (same rows, same guarantees,
   linked to the README as the source of truth).
2. The install command, `npm install animspec`, copyable.
3. The quick-start example: validate, build a `SignalFrame`, draw. It MUST match the user
   guide's quick start; the guide is canonical, the page links it.
4. Links: user guide, software design document, gallery, contribute, npm package page,
   repository root.

### `/gallery/` (generated)

1. One card per registry primitive (SC-003): thumbnail with alt text, `type` (heading), `category`,
   `tier`, `description` verbatim from the registry, and a link to the primitive's entry in
   `src/primitives/registry.ts` on GitHub.
2. A `legacy` card names the primitive that replaces it, when `replacedBy` is set.
3. A lead-in sentence linking `VOCABULARY.md` for the full param tables: the card is a picture
   and a name, the vocabulary is the reference.

### `/contribute/` (contribute)

1. The new-primitive rule and the four style questions, summarised, each linking CONTRIBUTING.md.
2. The five steps in order: open a proposal issue from the template, implement one registry
   entry, run `npm run verify`, sign the CLA, open the pull request.
3. The gates behind `npm run verify`, stated as the contributor's one-command quality bar.
4. Links: the primitive-proposal template, the CLA, `good first primitive`, CONTRIBUTING.md,
   the user guide's "write a spec" material for trying primitives before proposing one.

## Asset rules

- Stylesheet: `site/assets/style.css`, handwritten, monochrome by default. The visual language
  mirrors the library's palette discipline: near-black background, off-white foreground, one
  accent used sparingly.
- Fonts: `@font-face` declarations over the shipped font files copied to `site/assets/fonts/`,
  each with its licence text beside it, with a system monospace fallback stack. A page MUST NOT
  load a font from any other origin.
- Thumbnails: `site/assets/gallery/<type>.png`, copied by the generator, alt text on every one.
- A page load MUST issue zero requests to origins other than the site's own (SC-004). No
  analytics, no CDN, no web fonts, no images from outside the artifact.

## Accessibility and semantics

- Semantic HTML: one `<h1>` per page, headings in order, a `<nav>` landmark, lists for steps.
- Every image has alt text; thumbnail alt text is `"<type>: <description>"`.
- Text meets WCAG AA contrast in both the dark default and any light variant.
- The site works with JavaScript disabled: no script is required for any content or navigation.

## 404 behaviour

An unknown path returns GitHub Pages' default 404. No custom error page at v1 (out of scope,
recorded here so its absence is a decision, not an oversight).
