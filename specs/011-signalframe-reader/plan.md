# Plan: SignalFrame Per-Frame Reader and Conformance Fixture

## Summary

Add random-access reading to the SignalFrame track format without changing one byte on
disk: `readSignalTrackHeader` parses the 32-byte preamble once, `readSignalFrame` reads
exactly one record at `32 + n·stride` from any `Uint8Array` view (including a memory-mapped
file), and a sidecar index helper parses the NDJSON once per file. A committed conformance
fixture (`golden/signalframe/sample.asft` + sidecar), generated by the encoder itself and
pinned by SHA-256, gives writers in other languages a byte-level target the verify gate
enforces. The contract's sidecar unknown-field rule is stated plainly (v1 readers ignore
unknown fields — what the codec does today).

## Approach

1. **Reader API** (`src/signalframe/index.ts`, the format's single home): the three reader
   functions over `DataView` on the caller's view, honouring `byteOffset`/`byteLength`,
   applying the decoder's validation — header stage for `readSignalTrackHeader`, record +
   sidecar stage for `readSignalFrame`. No new dependency, no I/O, no ambient randomness.
2. **Public surface** (`src/index.ts`): export the three functions and the header/index
   types.
3. **Conformance fixture** (`golden/signalframe/sample.asft` + `sample.asft.ndjson`): a
   fixed in-repo sample track (4 frames, 4+4 bands, one frame with `labels` and `coords`)
   encoded once by the encoder and committed; the gate re-encodes, compares bytes and the
   pinned SHA-256, and decodes both ways asserting pinned values.
4. **Gate** (`scripts/verify-signalframe.ts`): the fixture and per-frame equivalence checks
   join the existing round-trip gate; still one step in the `verify` chain.
5. **Contract wording** (`specs/008-signalframe-format/contracts/signalframe-format.md`):
   the sidecar section states the v1 rule in one sentence; "Extending the format" states
   that a validation tightening bumps `version`.
6. **Governance**: constitution amendment ("The format" gains the reader and fixture,
   Quality Gates row, version MINOR) in the same change.

## Gates and golden hashes

- **Touched**: `verify:signalframe` gains the fixture byte/hash checks and the
  per-frame-equals-whole-track equivalence; `verify:package` sees three new exports.
  Purity scan unchanged and still passing (byte-level only, no file/network import).
- **Golden render hashes**: **no movement**. Nothing that renders changes; the reference
  sets, `golden/CHANGES.md` and `golden:update` are untouched. The fixture lives under
  `golden/signalframe/`, which no render hash covers.

## Constitution Check (Principle VII)

- **Boundary change**: yes. A random-access reader is a new kind of public export and a new
  promise to callers; the baseline's "The format" entry and the Quality Gates table are
  amended in the same change that ships it (FR-009).
- **Principles**: I (a frame read per-frame is bit-identical to the same frame read
  whole-track), III (byte-level only; the caller does file I/O and mapping), IV (sidecar
  data stays validated, untrusted input never guessed), VI (checks run inside the one
  offline `verify`; measured cost: a few milliseconds — the fixture is 4 frames), VII (six
  boundary entries in `spec.md`; amendment shipped with the feature).

## Out of scope

File I/O and memory-mapping, audio decode/FFT, format or version changes, compression, a
CLI track inspector (a possible later spec).
