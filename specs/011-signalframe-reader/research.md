# Research: SignalFrame Per-Frame Reader

Decisions behind the reader and the fixture. Each is a choice with a determinism or
compatibility consequence.

## R1. Byte-offset arithmetic, not an index table

The format is fixed-stride: frame *n* begins at `32 + n·stride`. Random access needs no
side table, no scan, and no format change — the stride already *is* the index.

**Decision**: compute offsets arithmetically from the header. Alternatives rejected: an
offset table (changes the on-disk bytes — the issue forbids it), a streaming/cursor decoder
(new abstraction the constitution's default answer says no to).

## R2. The header reader validates the exact total length

`readSignalTrackHeader` applies the decoder's full header-stage validation, including
"length is exactly `32 + frameCount * stride`", before any frame is read.

**Decision**: validate once in the header, not lazily per frame. Rationale: the spec's
requirement is "the same validation as the whole-track decoder", and a worker mapping a
file already holds the whole view, so exactness costs nothing. A truncated file fails
loudly at header time instead of mid-render.

## R3. `readSignalFrame` takes the parsed header, not the raw bytes alone

**Decision**: signature is `(bytes, header, n, sidecar?)`. The caller parses the header
once and reads many frames; validation runs once per file, not once per frame.
Alternatives rejected: re-parsing the header inside every call (wasteful, invites
inconsistent validation), and a stateful reader object (a class with internal position —
more surface than this feature needs, and the repo prefers plain functions).

## R4. A sidecar index helper, because validation must not be duplicated

A worker applying `labels`/`coords` to hundreds of frames should not re-parse the NDJSON
per frame, and must not hand-roll the validation (that is how two readers drift).

**Decision**: export one helper that parses the sidecar once into a per-frame lookup with
the decoder's validation, byte for byte.

## R5. The sidecar unknown-field rule: v1 ignores

The contract's sentence "A reader ignores no fields; unknown fields on a line are rejected
in a future version" is a double negative that reads both ways, and the "Extending the
format" section implies old readers never see new fields. The v1 codec (`parseSidecar`)
reads `index`, `labels` and `coords` and **skips every other key without error** — the code
defines the rule.

**Decision**: the contract states plainly that **v1 readers ignore unknown sidecar
fields**, and that recognised fields with the wrong shape are still rejected. A later
version MAY tighten this to a rejection; because that changes what a reader accepts, it
bumps `version` under the existing extension rule. Flipping the rule to "reject" would be
a behaviour change to the v1 codec, which this feature explicitly does not make.

## R6. The fixture is generated bytes, pinned — never hand-written

Hand-crafted test bytes would violate the repository's provenance rule ("never fabricate or
copy reference data") and could disagree with the encoder in ways nobody notices.

**Decision**: the sample track is defined in-repo (4 frames, `valuesLen = spectrumLen = 4`,
varied levels, one frame with `labels` and `coords`), encoded by `encodeSignalTrack`, and
the bytes are committed once. The gate re-encodes and compares byte-for-byte, pins the
file's SHA-256, and asserts pinned decoded values — so encoder drift, a tampered fixture,
or a hash mismatch each fail `npm run verify`.

## R7. Views, not copies

A memory-mapped file arrives as a `Uint8Array` view with a non-zero `byteOffset` inside a
larger buffer.

**Decision**: every reader constructs its `DataView` from the view's own
`byteOffset`/`byteLength` (the decoder already does this) and never copies the track. The
purity scan stays green: no file access anywhere in `src/`.

## R8. One home for the format's code

**Decision**: the readers live in `src/signalframe/index.ts` beside the codec — one
module owns the format. A separate `signalframe-reader.ts` would split a single
responsibility across files for no benefit. Zero new dependencies; `NOTICE` unchanged.
